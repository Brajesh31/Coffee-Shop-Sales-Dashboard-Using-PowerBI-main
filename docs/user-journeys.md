# 🧭 User Journeys

## Purpose
The intended analyst journey is: discover repository, download or clone, open PBIX, resolve workbook path, refresh, inspect headline KPIs, set date/filter context, compare locations/categories/products, inspect daily and day-hour patterns, validate a finding, and communicate a qualified conclusion.

## Current project context
At each step, record artifact, user action, expected outcome, common failure, recovery guide, and evidence needed. The journey does not include login, registration, or user-account creation.

## Recommended workflow
Always capture selected date range and active filters. Verify KPI semantics and independently reconcile material findings before using them for decisions. The user-journey SVG visualizes this sequence.

## Evidence and verification
Do not equate analytical-topic headings with actual PBIX page names. Verify the navigation model directly.
