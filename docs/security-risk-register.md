# 📊 Security Risk Register

## Purpose
Initial risks to assess include public workbook exposure, credentials in PBIX metadata or M expressions, excessive workflow permissions, unreviewed third-party actions, overbroad Power BI sharing, and malicious assets.

## Current project context
For each risk record asset, threat actor, attack path, likelihood, impact, controls, residual risk, owner, treatment, due date, and evidence. Revisit after changes to source, visibility, workflows, or Service sharing.

## Recommended workflow
This is an assessment register, not a completed security audit. Do not pre-assign risk scores without owner review.
