# ⌨️ Keyboard Navigation

## Purpose
Keyboard access must be tested in the actual Power BI Desktop or approved Service viewing environment.

## Current project context
The report's tab order and focus behavior have not been audited. A slicer or visual being clickable with a mouse does not establish keyboard accessibility.

## Practical process
Inspect focus order, visible focus, keyboard operation of slicers and navigation, data-table access, and ability to reset or change filter context without a mouse. Test the main analyst journey and document blockers by page and visual.

## Verification and boundaries
Do not claim keyboard accessibility until the real PBIX has been tested.
