# 🧑‍💻 Development Workflow

## Purpose
Begin from the current main branch, inspect existing files, create a local working copy, and preserve the original PBIX and workbook. Make one coherent change and identify the business question it addresses.

## Current project context
Report changes must be made in Power BI Desktop. Documentation and SVG changes can be reviewed as text in GitHub.

## Recommended workflow
Refresh after source or model changes; reconcile key measures; test filters and visuals; capture genuine evidence; update affected docs; run scripts/validate_docs.py; and review security/accessibility before release.

## Evidence and verification
A documentation check cannot prove PBIX correctness. A report change is incomplete when KPI, model, visual, or refresh documentation is stale.
