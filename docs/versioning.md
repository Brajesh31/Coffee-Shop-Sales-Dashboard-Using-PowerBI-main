# 🏷️ Versioning Policy

## Purpose
Use Git commits to preserve repository history. Keep PBIX and XLSX versions paired and record the matching commit SHA.

## Current project context
The project has not established a historical semantic-versioning convention. Do not imply old commits followed a version policy unless tags prove it.

## Recommended workflow
Adopt release tags only after owner approval. For every release record source hash, report hash, Desktop build, change summary, validation status, and known limitations.

## Evidence and verification
A source schema change is a compatibility change even if the PBIX opens. Keep an approved prior artifact pair for rollback where data rights allow.
