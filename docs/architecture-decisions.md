# 🗂️ Architecture Decisions

## Purpose
Significant changes to source strategy, model design, date intelligence, KPI definitions, refresh method, visual architecture, security controls, or publishing approach should have a recorded decision.

## Current project context
The repository has an existing ADR template and decision log. Historical intent of the original PBIX is not fully known; do not invent old decisions.

## Practical process
Create one ADR for a material decision. Record context, current evidence, options, trade-offs, chosen path, consequences, validation, owner, and status. Link it from decision-log.md and update relevant technical guides.

## Verification and boundaries
Minor formatting changes do not need ADRs. Decisions that affect data semantics, access, or reproducibility usually do.
