# 🧱 Technical Debt Register

## Purpose
Potential debt includes undocumented schema, unrecorded DAX definitions, missing genuine page screenshots, binary-only model metadata, manual refresh validation, and limited automated coverage of PBIX behavior.

## Current project context
Prioritize by risk to correctness, reproducibility, security, accessibility, and future changes. Record current pain, impact, proposed improvement, effort, dependencies, and acceptance evidence.

## Recommended workflow
Do not create speculative refactor tasks. Link each debt item to an observed limitation or a clearly stated improvement need.

## Evidence and verification
Use the risk register when debt creates a material project risk.
